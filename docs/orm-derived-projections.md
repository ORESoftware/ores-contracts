# ORM-derived projections

This document defines the ORES derivative-schema lane for private Rust ORM repositories.

The motivating developer experience is similar to Drizzle's `createSelectSchema` / `createInsertSchema`: define the persistence model once, then derive role-specific validation/types from it. The ORES version must preserve two additional boundaries:

1. `*-orm-core` is private and backend-only; ORM rows are never automatically public API models.
2. Human-authored TypeSpec and Draft 2020-12 JSON Schema remain independent peer authorities. ORM-derived schemas are downstream evidence and must not overwrite either authority.

## Data flow

```text
reviewed SeaORM / Diesel definitions in *-orm-core
                 |
                 | ores-orm-core derive/adapter
                 v
       ores.orm-descriptor/v1
                 |
        +--------+---------+----------+----------+
        |                  |          |          |
        v                  v          v          v
  Rust/Serde          TS + Zod      Dart      Gleam
 select/insert/       validators   validators  decoders
 update/public
        |
        +------------------+
                           v
                 JSON Schema witness
                           |
                           v
                TJSV projection/runtime
                     admission evidence
```

The descriptor is generated evidence. It is not edited by hand and it is not a third contract authority.

## Shared Rust ownership

The preferred owner of the Rust extraction/derive implementation is the shared `ORESoftware/ores-orm-core` crate/repository. It should expose ORM-neutral metadata traits plus SeaORM and Diesel adapters.

`ores-contracts` owns the descriptor/projection semantics and convergence checks. TJSV owns cross-language/runtime admission. `ores-wit` may project an admitted public contract to WIT when useful; WIT does not become the persistence or public source of truth.

A product ORM crate should not parse its own Rust source text to recover schema information. Prefer proc macros/traits generated by the Rust compiler from normal model definitions. Source-text scraping is too sensitive to formatting, macro expansion and Diesel/SeaORM implementation details.

## Derived shapes

One database model produces multiple shapes. The minimum required set is:

- **Select** — fields returned by the persistence model;
- **Insert** — writable creation fields; generated/default identity fields are optional or absent;
- **Update** — mutable fields only, normally optional at the patch boundary;
- **PublicSelect** — explicit public allowlist only.

A future `Filter` shape may be generated where query/filter semantics are explicitly declared. It must not be inferred from every selectable field.

Nullability and optionality are different. A nullable column can still be required on insert. A non-null column with a database default can be optional on insert. Generators must preserve that distinction.

## Public exposure is fail-closed

Serde's `Serialize` is not a public-security annotation.

Every model that enables a public projection must classify every field as one of:

- `public`
- `private`
- `secret`

`unclassified` is allowed only while a model has no public surface. Enabling `PublicSelect` with any unclassified field must stop generation.

A likely Rust annotation surface is:

```rust
#[derive(OresOrmContract)]
#[ores(public_surface)]
struct AccountRow {
    #[ores(public, generated, read_only)]
    id: Uuid,

    #[ores(public)]
    email: String,

    #[ores(secret)]
    password_hash: String,

    #[ores(private, generated, read_only)]
    created_at: DateTime<Utc>,
}
```

The exact proc-macro spelling belongs to `ores-orm-core`; the semantics above are the stable contract.

## Descriptor v1

The machine contract lives at:

`contracts/orm-derived/v1/descriptor.schema.json`

It records:

- exact producing repository/revision/crate/toolchain;
- participating ORM adapters (`seaorm`, `diesel`);
- namespace, model and table identities;
- stable Rust/wire/database field names;
- logical scalar or enum type;
- nullability and array shape;
- generated/default state;
- select/insert/update eligibility;
- public/private/secret classification;
- constraints and relations;
- reviewed historical wire/database names for compatibility checks.

The producer must sort fields/relations deterministically and emit canonical JSON before hashing it.

## Rust schema generation

Rust DTOs should derive Serde. Where representable, they should also derive Schemars `JsonSchema` so the JSON Schema witness follows the actual Serde representation.

That Schemars document is a projection witness. It is compared/admitted against the independently authored public contract; it is never promoted to authored authority simply because it came from Rust.

Validation should be typed in Rust rather than only delegating to JSON Schema at runtime. Constraint attributes should drive both typed validation and schema generation when the semantics are equivalent.

## TypeScript

Generate:

```text
generated/typescript/
  account.types.ts
  account.zod.ts
```

Zod should expose separate schemas for select, insert, update and public select rather than one permissive object. Unknown fields must be rejected on API boundaries unless the authored contract explicitly says otherwise.

## Dart

Generate immutable models plus parsing/validation helpers for the same shapes. The Dart layer must preserve integer-width, UUID/date-time and enum constraints instead of reducing every scalar to `dynamic` or unconstrained `String`.

## Gleam

Generate Gleam records/custom types plus JSON decoders/validators for the same shapes. Unsupported representation differences must be explicit projection findings, never silent weakening.

## WIT

WIT is optional and downstream. An admitted public projection can be fed into `ores-wit` for component/native binding generation. Private database columns and ORM relation metadata do not belong in WIT.

## CI contract

A product using this lane should run:

1. compile the exact SeaORM/Diesel model head;
2. emit `ores.orm-descriptor/v1`;
3. if both ORMs are present, require their normalized descriptors to agree;
4. generate Rust/TS/Dart/Gleam projections;
5. run the same positive/negative fixture corpus in all declared runtimes;
6. run TJSV current-input/projection/runtime admission;
7. fail if generated output differs from committed/package output;
8. package only admitted public artifacts into `*-interfaces` / `*-clients`.

A private `*-orm-core` must never become a runtime dependency of a public client package merely to obtain generated types.

## Fleet placement

| Repository | Role |
| --- | --- |
| `*-orm-core` | private Diesel/SeaORM models, descriptor export, persistence implementation |
| `*-lib-core` | framework-neutral domain/use-case code; no raw ORM models |
| `*-interfaces` | authored peer authorities and admitted public projections/provenance |
| `*-clients` | generated Rust/TS/Dart/Gleam client validation packages |
| `ores-contracts` | descriptor/projection semantics and persistence convergence |
| `typespec-json-schema-validator` | parity, current-input binding and runtime/projection admission |
| `ores-wit` | optional WIT/component projection tooling |

This avoids the two failure modes seen in older experiments: duplicating ORM models into every language manually, and accidentally treating a generated schema as the new contract authority.
